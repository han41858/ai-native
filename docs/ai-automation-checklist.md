# AI 개발 자동화 도입 및 검증 체크리스트

[AI 개발 자동화 지침](ai-automation.md)의 적용 여부를 확인하는 체크리스트입니다. 각 프로젝트의 최신 기준 브랜치에서 기존 구현과 비교하고, 이미 충족하는 항목은 변경하지 않습니다.

## 적용 기록

- 검토한 ai-native 커밋 SHA:
- 프로젝트 기준 브랜치 및 검토한 SHA:
- 개발·리뷰 모델 및 실행 승인 방식:
- 자동 머지 대상 및 프로젝트별 검증 명령:
- 미충족·적용 제외 항목과 이유:
- 검증 방법 및 미확인 사항:

각 항목은 충족, 개선 필요, 적용 제외, 미확인으로 구분합니다. 체크 표시만으로 충족을 판단하지 않고 관련 코드·설정·테스트를 확인합니다.

지침의 적용 원칙에 따라 프로젝트의 자동화 범위와 운영 환경에 해당하는 항목만 검토합니다. 권장 기능을 채택하지 않았거나 해당 기능을 사용하지 않는 경우에는 적용 제외로 기록하고 이유를 명시합니다. 체크리스트를 채우기 위해 불필요한 기능을 추가하지 않습니다. 적용 대상 기능의 보안·권한·작업 무결성·머지 안전성 요구사항은 생략하지 않습니다.

## 실행 및 상태 관리

- [ ] 승인된 Issue만 실행하고 저장소·작업 범위·대상 브랜치를 확인한다.
- [ ] 실행 전 및 주요 변경 경계에서 중단·수동 변경·승인 범위를 재확인한다.
- [ ] 동일 Issue 실행, 후속 이벤트 및 예약의 중복을 방지한다.
- [ ] 선행 작업의 실제 대상 브랜치 머지를 검증하고 대기 작업을 중복 없이 재개한다.
- [ ] 단계별 상태·HEAD·복구 횟수를 저장하고 실제 GitHub 상태와 대조한다.
- [ ] 대기, 복구, 중단, 사람 확인, 실패, 머지 및 최종 완료를 구분한다.

## 모델과 편집

- [ ] 개발자와 리뷰어가 독립적이며 공급자·모델 설정을 변경할 수 있다.
- [ ] 개발·리뷰·전체 작업의 호출·토큰·시간·복구 예산을 제한한다.
- [ ] 최종 결과 제출 및 교정 예산을 확보한다.
- [ ] 탐색 한도에 도달해도 허용된 결과를 반환하며 검색·부분 읽기를 지원한다.
- [ ] 스트리밍의 분할 이벤트, 다중 도구 호출, 연결·본문·완료 오류를 구분한다.
- [ ] Claude의 기존 지침·도구 정의·메시지·서명된 thinking을 보존한다.
- [ ] 완료·미완성·사람 확인 필요를 구분하고 미완성 결과를 게시하지 않는다.
- [ ] 스키마와 실제 검증 제약이 일치하며 형식 오류를 제한적으로 교정한다.
- [ ] 중단 사유가 없으면 설명을 요청하되 기존 중단 결정을 뒤집지 않는다.
- [ ] 원문 누락·중복 일치를 교정하며 부분 적용·게시 및 임의 유사 치환을 금지한다.
- [ ] 경로·파일 크기·테스트·설정 편집 범위를 검토하고 보호 경로를 강제한다.
- [ ] 커밋·PR 제목을 결정적으로 검증한다.

## 검증 및 리뷰

- [ ] 변경 파일의 자동 포맷을 먼저 적용하고 검증한 최종 내용만 게시한다.
- [ ] 자격 증명 없는 격리 환경에서 후보를 검사하며 검증 정책 우회를 방지한다.
- [ ] 잠금 파일과 신뢰된 도구로 의존성을 준비하고 캐시 오염을 방지한다.
- [ ] 변경 영향에 맞춰 검사를 수행하고 미확인·혼합 변경은 보수적으로 검사한다.
- [ ] 화면 변경 시 개발자와 리뷰어가 기존 UI 테스트를 확인한다.
- [ ] 검사 실패 단계와 정제된 진단을 구분하여 보완 요청에 전달한다.
- [ ] 같은 Issue의 기존 PR을 재사용하고 게시 응답 유실 시 실제 상태를 조회한다.
- [ ] 리뷰 결과와 필수 CI를 현재 HEAD에 연결하고 독립적으로 표시한다.
- [ ] 리뷰 지적은 개발자가 같은 PR에서 보완하고 새 HEAD를 다시 검증한다.
- [ ] 리뷰 형식 교정으로 지적이 사라지거나 승인으로 바뀌지 않도록 한다.
- [ ] CI 실패 진단을 기록하고, 자동 보완을 지원한다면 횟수를 제한하며 새 HEAD의 리뷰·CI를 요구한다.
- [ ] 댓글 실패 등에서 확인된 동일 HEAD의 리뷰를 안전하게 재사용한다.

## 기준 갱신·머지·종료

- [ ] 기준 변경을 감지하고 이전 기준의 검증 결과로 게시·머지하지 않는다.
- [ ] 자동 기준 복구를 지원한다면 게시 전에는 기존 후보를 폐기하고 제한적으로 재개하며, 게시 후에는 같은 PR을 갱신하고 새 HEAD를 재검증한다.
- [ ] 자동 충돌 해소를 허용한다면 범위·파일·횟수 제한과 충돌 표식 검사를 적용한다.
- [ ] PR 조회 지연과 실제 수동 변경을 구분하고 예상 밖 HEAD에서는 중단한다.
- [ ] 복구 예약과 횟수를 저장하며 전체 비용·실행 시간 상한을 유지한다.
- [ ] 사용자 승인 범위 내에서만 검증된 HEAD를 지정하여 머지한다.
- [ ] 브랜치 보호, 필수 CI 및 main 승격·릴리스 정책을 유지한다.
- [ ] 머지와 Issue 종료를 각각 실제 상태로 확인한다.
- [ ] 이미 머지된 PR의 종료 실패는 종료 단계만 재개한다.

## GitHub Actions·보안·관측성

- [ ] 토큰별·job별 최소 권한과 PR 댓글 권한을 확인한다.
- [ ] Secret과 신뢰되지 않는 코드·워크플로의 실행 경계를 격리한다.
- [ ] 워크플로 편집 권한과 자동화 자체 변경의 보호 정책을 확인한다.
- [ ] Issue·PR·리뷰·로그·모델 출력을 신뢰하지 않는 데이터로 처리한다.
- [ ] Actions SHA의 유효성, 이벤트 전달 및 후속 작업 권한을 확인한다.
- [ ] 관련 이벤트만 처리하고 불필요한 러너·모델 호출을 줄인다.
- [ ] 상태 규격, 실패 코드, 구체적인 사유, HEAD, 시간·토큰·복구 횟수를 기록한다.
- [ ] 로그·댓글에 비밀, 추론 서명 및 불필요한 원문을 남기지 않는다.
- [ ] 사람 확인이 필요한 중단은 사용자에게 명확하게 알린다.

## 장애 회귀 검증

다음 시나리오를 모의 응답·격리 검사 등 적절한 방법으로 재현합니다. 적용하지 않는 기능은 이유를 기록합니다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 탐색 한도 초과 | 허용된 결과 반환, 최종 응답 기회 확보 |
| 미완성 수정안 | 같은 대화로 계속 진행, 부분 게시 없음 |
| 형식·제목 오류 | 제한된 교정 또는 검증된 제목 사용 |
| Claude 분할 서명·후속 도구 요청 | 서명·대화 보존, 정상 요청 구성 |
| 연결 지연·본문 중단·완료 이벤트 누락 | 구체적 분류 및 요청 정리 |
| 편집 원문 누락·중복 | 전체 변경 재검증, 실패 시 미게시 |
| 보호 경로 편집 | 즉시 차단 |
| 포맷 위반 | 변경 파일 자동 포맷 후 실제 검사 |
| 격리 검사 실패 | 실패 단계 기록, 제한된 보완 |
| 댓글 쓰기 권한 부족 | 명확한 권한 오류, 동일 HEAD 결과 보존 |
| 리뷰 수정 요청·CI 실패 | 동일 PR 보완, 새 HEAD 재리뷰·재검사 |
| 기준 변경·텍스트 충돌 | 제한된 안전 복구 또는 사람 확인 |
| PR 조회 지연·API 쓰기 응답 유실 | 실제 상태 확인, 중복 게시 방지 |
| 선행 실패·완료·중복 이벤트 | 후속 대기 또는 단일 예약 재개 |
| 중단 라벨·수동 HEAD 변경 | 후속 게시·머지 차단 |
| 과거 HEAD의 리뷰·CI 성공 | 현재 HEAD 머지 불가 |
| 머지 성공 후 종료 오류 | 실제 종료 확인 또는 종료만 재개 |
| 전체 복구 예산 소진 | 추가 자동 실행 중단 |

## 실제 운영 확인

- [ ] 모의 테스트 결과와 실제 격리 검사 결과를 구별해 기록했다.
- [ ] 작은 승인된 Issue로 모델 API → PR → 리뷰 → CI → 머지 → 종료를 검증했다.
- [ ] 실제 토큰 권한, 후속 이벤트, 재개 및 상태 표시를 검증했다.
- [ ] 미확인 항목은 미확인으로 남겼으며 운영 성공으로 단정하지 않았다.

새로운 공통 장애 사례는 회귀 테스트와 함께 ai-native 지침 갱신 대상으로 제안합니다. 다른 저장소는 별도 요청 없이 수정하지 않습니다.
